Hive — Réseau
de honeypots interactifs

Hive transforme l’activité dirigée vers des services leurres en télémétrie consultable en direct. Quatre capteurs Go observent les interactions SSH, HTTP, MySQL et Redis et transmettent des événements structurés à un tableau de bord React et TypeScript.

Points forts techniques

Un flux complet de l’événement à l’opérateur

Le projet met en œuvre la gestion de protocoles réseau, la diffusion concurrente d’événements, l’assainissement des entrées, le stockage journalisé, la conception d’API et de WebSocket, le déploiement conteneurisé et une interface pensée pour les opérateurs.

Des capteurs adaptés aux protocoles

Des capteurs Go distincts observent SSH, HTTP, les échanges d’authentification MySQL et le trafic Redis RESP. Chacun produit des événements au format commun, avec un comportement volontairement limité au leurre.

  • Le capteur HTTP héberge un site leurre et journalise les clics sur les liens ainsi que les soumissions de formulaire.
  • Le capteur MySQL analyse une poignée de main de connexion limitée et répond par un refus d’accès.
  • Le capteur Redis traite un ensemble limité de commandes en ligne et RESP.

Diffusion maîtrisée des événements

Un bus d’événements typé ajoute des identifiants et les métadonnées du capteur, applique des étiquettes ATT&CK heuristiques, alimente le journal, conserve une fenêtre récente en mémoire et distribue les événements dans des files d’abonnés de taille limitée.

  • Les clients lents du tableau de bord ne bloquent pas les capteurs.
  • Les pertes de diffusion et les erreurs d’écriture du journal apparaissent dans les indicateurs d’état opérationnel.
  • Le tableau de bord associe la recherche dans le journal à un flux WebSocket qui se reconnecte automatiquement.

Des résultats utiles et vérifiables

Les opérateurs peuvent consulter les détails des événements, rechercher dans l’historique conservé, exporter les résultats filtrés en CSV et examiner les artefacts de renseignement sur les menaces.

  • Les adresses IP sources valides peuvent être exportées comme indicateurs STIX 2.1.
  • Les commandes pare-feu suggérées sont écrites dans un fichier destiné à une vérification manuelle.
  • Les correspondances ATT&CK sont des heuristiques d’analyse, et non une preuve d’intention malveillante.

Voir Hive en action

Le tableau de bord donne à l’opérateur tout le contexte

L’interface réunit dans un même flux d’analyse l’activité des capteurs en direct, l’historique conservé, l’état de diffusion et un aperçu interactif du site leurre. Cliquez sur une capture pour l’agrandir ; vous pourrez ensuite parcourir les images de la galerie.

  • Rechercher des événements par requête et par service.
  • Ouvrir un événement pour consulter ses détails structurés.
  • Surveiller l’état des abonnés et du journal.
  • Exporter au format CSV les résultats filtrés.

Parcourir le scénario

Lancer Hive dans un laboratoire isolé

Le projet source requiert Go 1.26.4 ou une version ultérieure, ainsi que Node.js 20.19+ ou 22.12+ avec npm. Depuis la racine du dépôt, lancez les services locaux et laissez le terminal ouvert :

Démarrage local
$ ./run-local.sh
Tableau de bord : 127.0.0.1:5173
Site leurre : 127.0.0.1:8080
API d’état : 127.0.0.1:8000/api/health

1 · Explorer le site leurre

Ouvrez le tableau de bord, choisissez Site leurre dans la barre latérale, puis utilisez la navigation et les liens d’action. La page reste chargée tandis que Hive reçoit les événements de clic.

2 · Envoyer le formulaire de démonstration

Le formulaire de contact affiche une confirmation simulée et journalise les noms des champs envoyés. Ce point de terminaison ne conserve pas les valeurs saisies.

3 · Se connecter au leurre SSH

Dans un second terminal, connectez-vous avec ssh -p 2222 root@127.0.0.1, saisissez n’importe quel mot de passe, puis essayez whoami ou ps. Le faux shell journalise les commandes sans les exécuter sur la machine hôte.

Générer du trafic de démonstration

Une simple requête HTTP suffit à générer un événement de démonstration :

curl http://127.0.0.1:8080/wp-login.php

Si les outils clients sont installés, vous pouvez également tester des connexions Redis et MySQL :

redis-cli -h 127.0.0.1 -p 6379 PING
mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u demo

Limites et traitement des données

Des leurres conçus avec des limites explicites

Hive est un laboratoire de sécurité en développement, et non une plateforme SOC prête pour la production. Les protocoles sont volontairement limités ; les données recueillies et les résultats générés doivent être vérifiés par un opérateur.

Données recueillies par chaque capteur

  • SSH : noms d’utilisateur et commandes ; les mots de passe sont écartés. Le shell est simulé et n’exécute aucune commande sur l’hôte.
  • HTTP : méthode, chemin, agent utilisateur, corps de requête limité, clics sur les liens du leurre et noms des champs de formulaire. Les valeurs du formulaire sont écartées ; d’autres corps de requête peuvent néanmoins contenir des données sensibles.
  • MySQL : nom d’utilisateur extrait d’une poignée de main limitée. Le capteur ne stocke pas la réponse contenant le mot de passe et ne prend pas en charge les sessions SQL.
  • Redis : commandes issues de requêtes en ligne et RESP ; les valeurs AUTH et les affectations de secrets courantes sont masquées.

Limites opérationnelles

  • Le journal local est un fichier JSONL à rotation, et non une base indexée ; la recherche parcourt des fichiers de taille limitée.
  • Les étiquettes ATT&CK sont heuristiques et les indicateurs IP sont des pistes d’analyse, pas des conclusions.
  • Le navigateur conserve jusqu’à 500 événements ; une file d’abonné saturée peut entraîner la perte d’événements en direct.
  • Le masquage des données est effectué au mieux. Avant toute collecte hors d’un laboratoire local, vérifiez les règles de conservation, d’accès et les obligations légales.
  • Les suggestions de règles pare-feu sont indicatives. Vérifiez-les et adaptez-les manuellement ; n’exécutez jamais directement le fichier.

Sécurité du déploiement

Utilisez Hive comme capteur, pas comme infrastructure de production. Ses points de terminaison SSH, web, MySQL et Redis sont des leurres, pas des services de production.

  • Par défaut, les écouteurs se lient à 127.0.0.1 pour un usage local.
  • Gardez l’API du tableau de bord privée. Si elle est liée à une adresse autre que loopback, configurez le jeton Bearer requis et limitez l’accès à un réseau privé de confiance.
  • Pour exposer volontairement un capteur sur le réseau, utilisez une machine dédiée et isolée, sans identifiants de production ni données sensibles.
  • Les règles pare-feu suggérées ne sont jamais appliquées automatiquement.

Le profil Docker Compose publie par défaut les ports sur loopback, conserve les données dans un volume, retire des capacités Linux aux conteneurs et rend le système de fichiers du service backend en lecture seule, à l’exception du volume de données.
