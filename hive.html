Hive — Interactive
Honeypot Network

Hive turns activity against decoy services into searchable, live telemetry. Four Go sensors observe SSH, HTTP, MySQL, and Redis interactions and stream structured events to a React and TypeScript operator dashboard.

Engineering highlights

A complete event-to-operator workflow

The project demonstrates network protocol handling, concurrent event delivery, input sanitization, journaled storage, API and WebSocket design, containerized deployment, and an operator-focused interface.

Protocol-aware sensors

Separate Go sensors observe SSH, HTTP, MySQL handshakes, and Redis RESP traffic. Each emits a shared event shape while keeping protocol behavior intentionally limited to a decoy.

  • HTTP includes a decoy website and records link clicks and form submissions.
  • MySQL captures a bounded login handshake and responds with access denied.
  • Redis handles a limited set of inline and RESP commands.

Bounded event delivery

A typed event bus enriches events with IDs and sensor metadata, applies heuristic ATT&CK tags, writes the journal, keeps a recent in-memory window, and fans out to bounded subscriber queues.

  • Slow dashboard clients do not block sensor handlers.
  • Dropped deliveries and journal errors are surfaced as operational health signals.
  • The dashboard combines journal search with a reconnecting WebSocket feed.

Useful, reviewable outputs

Operators can inspect event details, search retained history, export filtered results to CSV, and review threat-intelligence artifacts.

  • Valid source IPs can be represented as STIX 2.1 indicators.
  • Suggested firewall commands are written to a file for manual review.
  • ATT&CK mappings are investigative heuristics, not proof of malicious intent.

See it in action

The dashboard keeps the operator in context

The interface brings live sensor activity, retained history, delivery health, and a connected decoy-site preview into one investigation workflow.

  • Search events by query and service.
  • Open an event for its structured details.
  • Review subscriber and journal health signals.
  • Export the currently filtered results to CSV.

Try the workflow

Run locally in an isolated lab

The source project requires Go 1.26.4+ and Node.js 20.19+ or 22.12+ with npm. From its repository root, launch the local services and keep the terminal open:

Local launch
$ ./run-local.sh
Dashboard: 127.0.0.1:5173
Decoy site: 127.0.0.1:8080
Health API: 127.0.0.1:8000/api/health

1 · Explore the decoy site

Open the dashboard, choose Decoy website in the sidebar, then use its navigation and call-to-action links. The page stays loaded while link-click events are sent to Hive.

2 · Submit the demo form

The inquiry form returns a simulated confirmation and records which field names were submitted. Submitted values are discarded by this interaction endpoint.

3 · Connect to the SSH decoy

In a second terminal, connect with ssh -p 2222 root@127.0.0.1, enter any password, and try whoami or ps. The fake shell records commands; it does not run them on the host.

Generate sample traffic

A simple HTTP request is enough to create a sample event:

curl http://127.0.0.1:8080/wp-login.php

If the client tools are installed, Redis and MySQL also accept sample connections:

redis-cli -h 127.0.0.1 -p 6379 PING
mysql --protocol=TCP -h 127.0.0.1 -P 3306 -u demo

Boundaries and data handling

Decoys by design, with clear limits

Hive is a development-stage security lab, not a production SOC platform. Protocol behavior is intentionally limited; collected data and generated outputs need operator review.

What each sensor records

  • SSH: usernames and commands; passwords are discarded. The shell is simulated and never executes host commands.
  • HTTP: method, path, user agent, bounded request body, decoy link clicks, and form field names. Form values are discarded; other request bodies can still contain sensitive input.
  • MySQL: username from a bounded handshake. The sensor does not store the password response or implement SQL sessions.
  • Redis: commands from inline and RESP requests, with AUTH values and common secret assignments redacted.

Operational limits

  • Local journal is rotating JSONL, not an indexed database; search scans bounded journal files.
  • ATT&CK tags are heuristic, and IP indicators are leads for investigation rather than verdicts.
  • The browser retains up to 500 events; a full subscriber queue can drop live deliveries.
  • Redaction is best effort. Review retention, access, and legal requirements before collecting beyond a local lab.
  • Firewall suggestions are advisory text. Inspect and adapt them manually; never execute the file directly.

Deployment safety

Run Hive as a sensor, not as production infrastructure. Its SSH, web, MySQL, and Redis endpoints are decoys, not production services.

  • Default listeners bind to 127.0.0.1 for local use.
  • Keep the dashboard API private. If the API binds beyond loopback, configure the required bearer token and restrict access to a trusted private network.
  • For deliberate network exposure, use a dedicated isolated host with no production credentials or sensitive data.
  • Suggested firewall rules are never applied automatically.

Container deployment uses a local Compose profile, loopback-published ports by default, a persistent data volume, dropped Linux capabilities, and a read-only backend filesystem except for its data volume.
